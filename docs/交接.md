## ⚠ 分階段 merge 與 GitHub 狀態不同步

決定是**累積完一個階段才一起併回 main**，不一張票併一次（memory：merge-in-stages-not-per-ticket）。
#1~#5、#23~#25 都維持 OPEN —— **那是刻意的**，併回 main 時 commit 裡的 `Closes #N` 會自動關票。
分支名 `fix/2-…` 其實是「這個階段」的分支，merge 前要不要改名屆時再定。

```bash
git log main..HEAD --oneline                                   # 這個階段累積了什麼
gh issue list --state open --json number,title --jq '.[] | "#\(.number) \(.title)"'
gh api repos/jimmy1688888/tesseract-ocr-/issues/18/dependencies/blocked_by --jq '[.[]|select(.state=="open")|.number]'
```

⚠ **pipeline.py 的檔案衝突**：#6、#7、#12~#15、#17、#18、#21 都動 `pipeline.py`（#27、#8~#10 主要動
`employer_extract.py`）。那是檔案衝突不是
邏輯相依，沒連相依邊 —— 實務上一次只開一張。
