## #2 做了什麼(已完成,供 review / merge 時參考)

分支 `fix/2-roster-is-not-a-gate`,3 個 commit:

| commit | 內容 |
|---|---|
| `e7b2e40` | 名冊載入失敗改成警告,不再進 preflight 結果列;`_check_dirs` 只剩「有沒有東西可處理」 |
| `e0f0322` | 修 code review 的四個缺口(見下) |
| `d90add1` | 釘住「`--file` 單檔模式也印名冊警告」這個取捨 |

**原本的 bug**:`_permit_lookup` 的設計、`_agency_cols` 查無回三個空字串、以及
preflight 自己印的那句「不影響許可證判讀」,三處都承諾降級不中斷,但 `_check_dirs`
把名冊載入失敗寫成 `ok=False` → `run_preflight` 回 False → `main` 直接 return,
**整批不跑**。

**code review 抓到、已修的四項**:

1. 驗收條件「B 欄有值、E~G 留空」原本只被 proxy 釘住(只證明 preflight 的門開了)。
   改成三段接力:① 真的寫一個壞掉的名冊檔 → 降級成 None;② 降級後 preflight 放行;
   ③ 放行後那一列 B 欄有值、E~G 三欄留空。少一段就不成立
2. `_warn_if_roster_unavailable` 的回傳值沒人用 → 改回 `None`
3. `_check_dirs` 多開的 `input_dir` 注入參數 → 刪掉,測試改用 `monkeypatch INPUT_DIR`
4. `fix` 與 `detail` 兩行印不同寫法的路徑 → 統一 `resolve()`

**新測試做過變異測試**(故意把程式改壞,確認測試會紅)。過程中抓到自己新寫的
`test_check_dirs_scans_the_dir_it_reports` 在任何變異下都不會紅 —— 它是空測試,
已換成釘份數的版本。**沒做過變異測試的測試,不能算守得住。**

**一個刻意的取捨**:`--file` 單檔模式(`require_input=False`)現在也會載名冊並印
警告。代價是連 `--preflight-only` 都要多等幾秒載 2.2MB;換到的是「不會跑完才發現
仲介欄空白」。已有測試釘住。

CONTEXT.md 同時新增「**閘門**」與「**降級來源**」兩個詞(新的「啟動與降級」段)。

### 九項決策共識(架構改了也照樣成立)

1. Gemini **只做離線比對**,不進 pipeline、不進證據模型、**不碰許可證**
2. 真值來自 Sheets **P 欄「已核」**由人簽的列
3. 走 **Vertex AI** 復用現有身分,不開 API key、不走免費層(個資不進訓練)
4. 模型 **Flash-Lite**;判錯的格再單獨重跑一次 Pro
5. **雙模式**診斷分解:文字模式測解析的錯、圖片模式測讀值的錯
6. 輸出要 **5 欄值 + 每欄來源依據原文**,不要自評信心分數
7. 等值判準**分欄不同**(姓名逐字嚴格不折疊、地址過 `fold_variants`)
8. 驗收 = 準確率提升 **且** 零新增安靜錯值(第二條是硬條件)
9. 「安靜錯值」立為 CONTEXT.md 術語

三個**明確否決**的選項(別再提):不讓 Gemini 讀許可證;不用 `upload_log.csv` 當真值
(它只記 B 欄,而且從未被寫出過 —— #6 選了刪掉,這條否決理由因此永久成立);
不走 AI Studio 免費層。
