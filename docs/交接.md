## ⚠ 分階段 merge 與 GitHub 狀態不同步

決定是**累積完一個階段才一起併回 main**,不一張票併一次。所以 #1、#2、#3 會維持 OPEN ——
**那是刻意的**。併回 main 時,commit 裡的 `Closes #1`(`3f99052`)、`Closes #2`(`e7b2e40`)、
`Closes #3`(`43400a1`)會自動關票。分支名 `fix/2-…` 其實是「這個階段」的分支,merge 前要不要
改名屆時再定。

GitHub 的 `blocked_by` **只數還開著的 blocker**,所以 GitHub 上 #4 仍顯示被 #2、#3 擋著、
#16 仍顯示被 #3 擋著 —— **以上方待辦清單為準**。

```bash
git log main..HEAD --oneline                                   # 這個階段累積了什麼
gh issue list --state open --json number,title --jq '.[] | "#\(.number) \(.title)"'
gh api repos/jimmy1688888/tesseract-ocr-/issues/4 --jq .issue_dependencies_summary.blocked_by
```

⚠ **pipeline.py 的檔案衝突**:#4、刀 ①②③、#12、#14、#17、#18 都動 `pipeline.py`。那是檔案衝突
不是邏輯相依,沒連相依邊 —— 實務上一次只開一張。
