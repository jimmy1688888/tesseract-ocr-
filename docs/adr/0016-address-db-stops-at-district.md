# 地址庫只到區:拿掉路名層,郵遞區號由縣市區表判定

地址庫原本有一層**路名**:用官方門牌庫(`data/AllData.json`,2.5 MB、不進版控)加上自建
補充檔(`data/custom_roads.json`)把 OCR 地址還原成標準中文地址(Sheets J 欄),並拿路名
當郵遞區號的佐證。2026-11-04 起整層拿掉:地址庫只剩**異體折疊**與**郵遞區號判定**,
資料改用一張隨 repo 版控的**縣市區表**(`data/tw_districts.json`,24 縣市、374 區,
縣市與區的中英官方名稱 + 3 碼郵遞區號)。

## 動機:維護成本

- 路名清單持續在長,官方庫也有漏收:補充檔兩週內補了 5 次,每次都是有人看到 J 欄空白、
  查證、手寫一條英譯、提交。
- 官方庫 gitignored,換機要另外帶;缺檔時安靜跳過,J、N 欄整批留空也不會有人發現。
- 縣市、區這一層幾乎不變(上次是縣市改制),而郵遞區號只需要到區。

## 留下的

- **異體折疊** `fold_variants`:permit_lookup 反查名冊在用,行為一行不改(ADR-0001)。
- **郵遞區號判定** `determine_zip`:縣市、區各自「精確含 → 去尾字 → 模糊」,精確含取最長
  命中;配區前先剝掉縣市名(32538);英文行錨定(縣市被紅章蓋掉時以英文行尾的官方英文
  縣市/區為錨,只做精確包含,所以算精確)。
- **寧空勿錯**:縣市精確命中、區也命中才填郵遞區號。
- **縣市中英不符**(33704):判出的中文縣市 ≠ 英文行精確包含的官方英文縣市名。
- 回傳一個有型別的值(郵遞區號、判出的縣市、`zip_blank_reason`、`city_mismatch`),
  事實**不冠欄名**;寧空勿錯、留空成因的優先序、縣市中英不符都住在地址庫。雇主擷取只做
  空輸入的事實、把兩類事實冠上欄名、門牌號比對。

## 刪掉的

- 官方門牌庫、路名補充檔、`.gitignore` 裡的 AllData 規則。
- 路名配對、路名反推行政區、英文路名備援、補充路名合併、路名查詢指令。
- 標準中文地址(`地址_中_標準` 永遠是空的;Sheets J 欄由 #30 拿掉)。
- 四條疑慮:地址庫無法使用、行政區未判定(該路名在多個行政區皆有)、路名未在該行政區的
  路名清單中、地址無路名樣式(鄉村型)。地址疑慮從 9 條剩 6 條。
- 快照的門牌庫雜湊:表進了版控,變了 git diff 看得到。

## 接受的代價

- **縣市非精確命中一律不填郵遞區號**。舊做法在路名配得到時把它當佐證(「宜藺縣羅東鎮
  中正路」救回宜蘭縣、265);路名層沒了就沒有其他佐證可以翻案。
- **區配不到就留空**。舊做法以「該路名在本縣市只屬於一個區」反推(32538 的文化七路 →
  龜山區、333);現在留空並寫「郵遞區號:行政區未判定」。
- 換來的是郵遞區號**只會變空、不會變成另一個值**:重錄快照時,郵遞區號由 A 變 B 即是 bug。
  2026-11-04 以 21 + 1 份既有全文與 15 份 Vision 素材驗過,郵遞區號一格都沒變。

## 讀不到表就拋出

舊的門牌庫缺檔時安靜跳過。縣市區表在 repo 裡,讀不到就是程式或安裝壞了,所以讓它拋出 ——
該份 docx 的擷取狀況變成「擷取失敗」,L 欄寫明原因,不會安靜地讓郵遞區號整批留空。
import 仍然零 I/O(ADR-0001),表在第一次判定時才載入並快取。不做注入:測試直接用真表,
表進了 repo,換機器不會大片轉紅。

## Considered Options

- **整個地址庫拿掉,郵遞區號也不產出**:郵遞區號在 Sheets 上有人用,而縣市區這一層幾乎
  零維護,沒理由一起丟。
- **保留路名層,只把門牌庫也放進版控**:解決換機問題,但不解決補充檔一直要補的問題。
- **選定:只拿掉路名層**(grill「Y+G+5」Q1 選 D)。
