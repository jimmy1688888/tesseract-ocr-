# 契約樣板由文件判定,整份一次

[CONTEXT.md](../../CONTEXT.md) 的「契約樣板」(家庭類／機構類／工廠類)決定雇主欄位怎麼擷取:
機構名、公司名那行不是英文地址,機構類與工廠類不做字數音節數檢查(ADR-0004)。
本 ADR 取代 ADR-0004 的兩處判定方式 —— 公司型「英文名含 Co/Ltd/Inc/Corp」與
機構型「英文名含機構字樣且不含數字」—— 改為**看文件印的樣板,整份判一次**,
由 `contract_template.py` 擁有字彙與判定。

## 起因

舊做法沒有「這份是哪一類」的判定,而是在英文地址、英文名、字數音節數檢查三處
**逐行從雇主英文名重猜**。文件其實早已寫明類別,卻沒被用上。工廠類素材(30766~30770)
進來後攤開了代價:`_EN_COMPANY` 的 `Corp\b` 認不得 `CORPORATION`(30767),英文名抓錯時
更無從猜起(30770 抓成 `CLI-6323`),兩份都掛了假的字數音節數疑慮。名字沒有機構／公司
字樣的機構或公司,在舊做法下一律當成個人。

## 判定順序

依 36 份 Vision 全文(10 份素材 + 5 份工廠類 + scan_results 舊 21 份)實測決定:

1. **中文標題** `勞動契約 ○○`:`監護工`/`家庭幫傭` → 家庭類,`養護機構`/`醫院` → 機構類,
   `工廠` → 工廠類。**36/36 讀得到**,一個訊號分得出三類
2. **印尼文標籤,單字即算**:`Perusahaan` → 工廠類、`Panti Jompo` → 機構類、`Majikan` → 家庭類。
   不要求 `Nama` 同行:工廠類 5 份的 `Nama Perusahaan` **全部**被 Vision 拆成兩行以上;
   家庭類的 `Nama Majikan` 有 5 份讀不到
3. **`SEKTOR INFORMAL`** → 家庭類。只有 `FORMAL` **不推定**:機構類與工廠類都是 FORMAL
4. 都沒有 → **認不出**

訊號矛盾(標題寫工廠類、標籤是 Majikan)以標題為準、不掛疑慮:矛盾只可能是 OCR 讀錯,
整行印刷大字的標題最可靠。

用 Vision 全文判,不用選契約頁時的 Tesseract 文字:那是 `extract_employer_fields` 的
同一個輸入,存下的全文能離線重放;Tesseract 讀得較髒(30767、30769 連標籤都沒讀到)。

## 認不出時照家庭類規則,並掛疑慮

認不出時套家庭類規則,L 欄掛 `H:契約樣板未辨識,以家庭類規則擷取`,逐行猜測**全部刪除**。
家庭類的檢查最嚴:若其實是公司或機構,字數音節數檢查會掛出看得見的假疑慮,而不是
看不見的錯值(ADR-0003)。保留逐行猜測當後備會讓判定又回到多處,失去「只判一次」的意義。
36 份中沒有一份認不出,這條疑慮實務上不製造雜訊。

## 刻意不做

- **不接選契約頁**:選頁用 Tesseract(`ind+eng`),讀不到最強的中文標題;15 份素材選頁全對,
  沒有要修的失敗。字彙寫在 `contract_template.py`,真的出現某類樣板選錯頁時再讓
  `_FORM_LABELS` 引用
- **不改區塊錨定的標籤**(`ID_LABEL`、`ID_LABEL_INSTITUTION`):錨定屬 #10 的範圍
